## 三、全局公共约定

以下约定为所有模块共用。各篇文档引用本节即可，无需重复展开。

### 3.1 统一响应结构

`com.macro.mall.common.api.CommonResult`：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| code | integer(int64) | 业务码 |
| message | string | 提示信息 |
| data | 泛型 | 业务数据 |

> **重要**：业务码定义在**HTTP 响应体内部**，HTTP 状态码通常仍为 200。前端须按 `code` 判断成败。

### 3.2 业务码

`com.macro.mall.common.api.ResultCode`：

| code | 常量 | message |
| --- | --- | --- |
| 200 | `SUCCESS` | 操作成功 |
| 401 | `UNAUTHORIZED` | 暂未登录或 token 已经过期 |
| 403 | `FORBIDDEN` | 没有相关权限 |
| 404 | `VALIDATE_FAILED` | 参数检验失败 |
| 500 | `FAILED` | 操作失败 |

> `VALIDATE_FAILED` 取 404 而非 400，与 HTTP 语义不一致，属历史设计。

### 3.3 分页结构

`com.macro.mall.common.api.CommonPage`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| pageNum | integer | 当前页码 |
| pageSize | integer | 每页条数 |
| totalPage | integer | 总页数 |
| total | integer(int64) | 总记录数 |
| list | array | 数据列表 |

由 `PageHelper` 分页后经 `CommonPage.restPage(List)` 转换，分页元数据来自 `PageHelper` 的 `ThreadLocal`。

### 3.4 网关路由

`mall-gateway`（:8201）为唯一入口，路由规则（`lb://` + Nacos 服务发现，`StripPrefix=1`）：

| 路由前缀 | 目标服务 |
| --- | --- |
| `/mall-auth/**` | `mall-auth` |
| `/mall-admin/**` | `mall-admin` |
| `/mall-portal/**` | `mall-portal` |
| `/mall-search/**` | `mall-search` |
| `/mall-demo/**` | `mall-demo` |

### 3.5 鉴权与白名单

**多账号体系**（Sa-Token）：

| 端 | 工具类 | login type | 用户表 |
| --- | --- | --- | --- |
| 后台管理员 | `StpUtil` | `login`（默认） | `ums_admin` |
| 前台会员 | `StpMemberUtil` | `memberLogin` | `ums_member` |

**网关鉴权逻辑**（`mall-gateway` 的 `SaTokenConfig`）：

1. `OPTIONS` 预检请求直接放行
2. 匹配白名单（`secure.ignore.urls`）则放行
3. `/mall-portal/**` → `StpMemberUtil.checkLogin()`
4. `/mall-admin/**` → `StpUtil.checkLogin()`
5. 从 Redis hash `auth:pathResourceMap`（常量 `AuthConstant.PATH_RESOURCE_MAP`）匹配当前请求路径所需权限，执行 `checkPermissionOr`

**白名单要点**（`mall-gateway/src/main/resources/application.yml`）：

| 类别 | 放行路径 |
| --- | --- |
| 文档 | `/doc.html`、`/*/v3/api-docs`、`/*/swagger-ui/**`、`/webjars/**` |
| 运维 | `/actuator/**` |
| 认证 | `/mall-auth/**` |
| 搜索 | `/mall-search/**` |
| 前台商城 | `/mall-portal/sso/login|register|getAuthCode`、`/mall-portal/home/**`、`/mall-portal/product/**`、`/mall-portal/brand/**`、`/mall-portal/alipay/**` |
| 后台例外 | `/mall-admin/admin/login`、`/mall-admin/admin/register`、`/mall-admin/minio/upload` |

> 即：**搜索与前台商城的大部分浏览类接口允许匿名访问**，后台接口除登录/注册/上传外均需鉴权。
>
> **注意**：`/mall-search/**` 整体放行；`/mall-portal/member/**`、`/mall-portal/cart/**`、`/mall-portal/order/**` **不在白名单**，需会员登录。

### 3.6 全局异常处理

`com.macro.mall.common.exception.GlobalExceptionHandler` 仅处理三类：

| 异常 | 返回 |
| --- | --- |
| `ApiException` | `CommonResult.failed(...)`，携带业务错误码 |
| `MethodArgumentNotValidException` | `code: 404`，message 为「字段名 + 默认信息」 |
| `BindException` | `code: 404` |

> **共性缺口**：未兜底 `Exception`。未捕获异常（如 `NullPointerException`、`MissingServletRequestParameterException`、数据库异常）会返回 Spring Boot 默认错误 JSON（结构为 `{timestamp, status, error, path}`），**不是 `CommonResult`**，前端统一处理会失效。

### 3.7 日志框架

| 项 | 内容 |
| --- | --- |
| 门面/实现 | SLF4J + Logback |
| 配置位置 | `mall-common/src/main/resources/logback-spring.xml`（各服务经依赖继承） |
| 控制台 | `CONSOLE` |
| 文件 | `FILE_DEBUG`（`logs/debug/${APP_NAME}-日期-序号.log`）、`FILE_ERROR`（`logs/error/…`），单文件默认 10MB、保留 30 天 |
| Logstash | 由 `logstash.enableInnerLog=true` 条件开启，4 个 TCP appender：`4560`(DEBUG) / `4561`(ERROR) / `4562`(业务) / `4563`(接口访问记录) |
| 访问日志 | `com.macro.mall.common.log.WebLogAspect`，切点为 `com.macro.mall.controller.*` 与 `com.macro.mall.*.controller.*`，覆盖 admin/portal/search/demo/auth |

**跨模块共性日志问题**（各篇会分别展开）：

1. `WebLogAspect` 中 `webLog.setIp(request.getRemoteUser())` 取值错误——`getRemoteUser()` 返回认证用户名而非客户端 IP。
2. `parameter` 会完整记录 `@RequestBody` 与 `@RequestParam` 参数，**登录/注册类接口会记录密码明文**。
3. `result` 完整记录响应体，列表类接口日志体积大。
4. 无 TraceId，跨服务（网关 → 服务 → Feign 下游）日志无法关联。
5. `logback-spring.xml` 使用 `NopStatusListener`，Logback 内部错误被静默。
6. 部分服务的 `application.yml` 与 Nacos 配置对 `logstash.enableInnerLog` 取值冲突（Nacos 优先级更高）。

### 3.8 JSON 序列化约定（**各篇返回示例均适用**）

**`mall-portal` 与其他服务的 null 字段行为不同**，编写与阅读返回示例时必须注意：

| 服务 | 是否配置 Jackson | null 字段行为 |
| --- | --- | --- |
| `mall-portal` | `config/JacksonConfig.java` 将 `@Primary` 的 `ObjectMapper` 设为 `JsonInclude.Include.NON_NULL` | **null 字段整体不出现在响应中**（键被省略），而非输出 `null` |
| `mall-admin`、`mall-search`、`mall-demo`、`mall-auth` | 未配置 | null 字段以 `null` 输出 |

该配置以 `@Bean @Primary ObjectMapper` 形式生效，会被 Spring MVC 的 `MappingJackson2HttpMessageConverter` 采用，**确实作用于 HTTP 响应**（非仅内部使用的 ObjectMapper）。

**由此产生两个容易踩的点**：

1. **`data` 为 null 时，`mall-portal` 的响应体中不存在 `data` 键**。例如查询不存在的记录，实际返回 `{"code":200,"message":"操作成功"}`，而不是 `{"code":200,"message":"操作成功","data":null}`。
2. **实体字段为空时该字段不出现在 JSON 中**（如 `PmsBrand.brandStory` 为空）。

> **文档口径**：《详细设计-品牌管理.md》的 3.3 节已按此修正示例。其余涉及 `mall-portal` 的文档（购物车与下单-前台、会员中心-前台、首页聚合）中若有 `"data": null` 或字段级 `null` 的示例，应理解为「该键不存在」；各篇的语义结论（如「查不到返回 data 为 null」）本身正确，仅字面呈现需按本节理解。

> **时间格式**：全仓库**未配置** `spring.jackson.date-format` / `time-zone`，也未使用 `@JsonFormat`，故 `Date`/`Timestamp` 按 Jackson 默认的 ISO-8601 序列化。各篇返回示例中的时间字面量多为示意，实际格式以联调为准。

## 四、接口清单的数据核对结论

在生成系列文档前，对 `../openapi.yaml` 与代码做了双向核对，结论如下。**这些结论影响各篇的接口描述准确性，请以本节为准。**

### 4.1 接口数量：237 而非 244

| 统计口径 | 数量 |
| --- | --- |
| `openapi.yaml` 中的 path 数 | **237** |
| `openapi.yaml` 中的 operation 数 | **237**（无 path 含多个方法） |
| Java 代码中的端点注解数 | **245** |
| Java 代码中的唯一路径数 | **238** |
| openapi 与代码匹配的路径数 | **237**（100% 匹配） |

**差异说明**：245 个端点注解对应 238 个唯一路径。差异**不是**「同一路径有多个 HTTP 方法」，而是**有 7 个路径被两个不同的控制器以相同路径重复声明**（跨服务同名，详见 4.3）。唯一未被导出到 openapi 的端点是：

| 方法 | 路径 | 归属 | 说明 |
| --- | --- | --- | --- |
| POST | `/alipay/notify` | `mall-portal` / `AlipayController` | 支付宝异步回调，未导出属正常（外部回调接口通常在文档中隐藏） |

### 4.2 接口无 tag，无法直接按 tag 分组

`openapi.yaml` 中 `tags` 字段完全缺失，`info.title` 为 `"API Documentation"`，`servers` 与 `security` 亦未定义。因此：

- 无法用 widdershins 直接生成带章节划分的文档；
- 本系列的归属划分改为**扫描 Java 控制器的类级 `@RequestMapping`** 建立「路径 → 模块 → 控制器」映射后确定。

### 4.3 跨服务同名路径（**影响接口描述准确性，务必阅读**）

#### 4.3.1 路径完全同名：导出时发生「遮蔽」

`openapi.yaml` 是**所有服务的聚合导出**，路径中**不含服务前缀**。以下 **7 个路径**由两个不同服务/控制器重复声明：

| # | 路径 | 方法 | 控制器 A | 控制器 B |
| --- | --- | --- | --- | --- |
| 1 | `/brand/listAll` | GET | `PmsBrandController`（mall-admin） | `DemoController`（mall-demo） |
| 2 | `/brand/create` | POST | `PmsBrandController`（mall-admin） | `DemoController`（mall-demo） |
| 3 | `/brand/update/{id}` | POST | `PmsBrandController`（mall-admin） | `DemoController`（mall-demo） |
| 4 | `/brand/delete/{id}` | GET | `PmsBrandController`（mall-admin） | `DemoController`（mall-demo） |
| 5 | `/brand/list` | GET | `PmsBrandController`（mall-admin） | `DemoController`（mall-demo） |
| 6 | `/brand/{id}` | GET | `PmsBrandController`（mall-admin） | `DemoController`（mall-demo） |
| 7 | `/order/list` | GET | `OmsOrderController`（mall-admin） | `OmsPortalOrderController`（mall-portal） |

由于 OpenAPI 以 **path 为唯一键**，这 7 个路径在导出时**只能保留一份定义**。经比对判据（`@Operation` summary 措辞、参数默认值、请求体 `required`、参数集合差异）可确认实际保留的是哪一方：

| 路径 | 判据 | openapi 保留的版本 |
| --- | --- | --- |
| `/brand/list` | summary「分页获取品牌列表」（demo 措辞，admin 为「根据品牌名称分页获取品牌列表」）、`pageSize` 默认 3（admin 为 5）、无 `keyword` 参数（admin 有） | **mall-demo** |
| `/brand/create`、`/brand/update/{id}` | 请求体 `required: [firstLetter, name]` 与 `PmsBrandDto`（demo，`name`/`firstLetter` 均 `@NotNull`）一致；admin 的 `PmsBrandParam` 要求 `name` + `logo` | **mall-demo** |
| `/order/list` | 含 `receiverKeyword`、`orderSn` 参数 | **mall-admin** |

**结论与影响**：

1. `openapi.yaml` 中这 6 个 `/brand/*` 路径的定义**代表 `mall-demo` 的示例接口，不代表 `mall-admin` 的业务接口**。若据此编写或联调 mall-admin 的品牌接口，会在参数默认值与必填校验上得出错误结论。
2. `mall-admin` 的 `PmsBrandController` 有 **9 个端点**，其中 6 个被遮蔽；未被遮蔽的 3 个为 `/brand/delete/batch`、`/brand/update/showStatus`、`/brand/update/factoryStatus`（demo 无此三接口）。
3. `mall-admin` 的 `OmsOrderController.list` 与 `mall-portal` 的 `OmsPortalOrderController.list` 同名，openapi 保留的是 mall-admin 版本；**前台订单列表接口的文档因此缺失**。
4. **运行期无冲突**：各服务为独立进程（8080 / 8082 / 8085），经网关后路径分别为 `/mall-admin/**`、`/mall-demo/**`、`/mall-portal/**`，互不干扰。**问题仅存在于文档聚合层面。**

**整改建议**（择一）：

- 按服务分别导出接口文档，或在导出工具侧配置保留服务前缀；
- 将 `mall-demo` 的示例接口路径改为独立前缀（如 `/demo/brand/**`）——更推荐，因为 `mall-demo` 是示例模块，不应占用与真实业务接口相同的路径。

#### 4.3.2 前缀同名但子路径不同

以下路径前缀在 `mall-admin` 与 `mall-portal` 中同时存在，但**子路径不同**，故未产生导出遮蔽；然而**仅凭路径前缀无法判断应访问哪个服务**，必须结合网关前缀：

| 路径前缀 | mall-admin | mall-portal |
| --- | --- | --- |
| `/brand` | `PmsBrandController` | `PortalBrandController` |
| `/product` | `PmsProductController` | `PmsPortalProductController` |
| `/order` | `OmsOrderController` | `OmsPortalOrderController` |
| `/returnApply` | `OmsOrderReturnApplyController` | `OmsPortalOrderReturnApplyController` |
| `/home` | `SmsHome*Controller` | `HomeController` |

> **编写各篇文档时的要求**：涉及上述路径前缀时，必须以「网关前缀 + 控制器」双重定位，不可仅凭 openapi 中的路径条目推断行为。

### 4.4 配置缺口

| 缺口 | 说明 |
| --- | --- |
| 缺 `mall-auth-dev.yaml` | `config/` 目录只有 `admin`、`demo`、`gateway`、`portal`、`search` 五个子目录；而 `mall-auth/application-dev.yml` 声明了 `spring.config.import: nacos:mall-auth-dev.yaml?refreshEnabled=true`（无 `optional:` 前缀），按仓库现状启动 `mall-auth` 会因拉不到配置而失败 |
| `logstash.enableInnerLog` 取值冲突 | 各服务 `application.yml` 与 Nacos 配置中的取值不一致（Nacos 优先级更高），导致 dev 环境 Logstash 日志实际不生效 |
| `sa-token.timeout` 不一致 | `mall-admin` / `mall-portal` 为 604800 秒（7 天），`mall-gateway` 为 2592000 秒（30 天） |

## 五、跨文档共性问题汇总

下列问题在多个模块中重复出现，各篇详述具体表现，此处汇总类型以便系统性整改：

| 类型 | 说明 | 典型出现位置 |
| --- | --- | --- |
| 缺索引 | 逻辑外键字段（`*_id`）普遍无索引，批量按外键更新时全表扫描 | `pms_product.brand_id` 等 |
| 无事务 | 多表写入的 Service 方法未标注 `@Transactional` | 品牌更新（含商品冗余同步）、优惠券创建（含关系表写入）等 |
| 冗余字段不同步 | 冗余的名称/快照字段在主表变更时未同步 | `sms_home_brand.brand_name`、`pms_product.brand_name` 等 |
| 无引用校验 | 删除主数据前不校验从表引用，产生孤儿数据 | 品牌、分类、活动、场次删除 |
| 参数无取值校验 | `@RequestParam` 上的枚举参数缺少校验（`FlagValidator` 仅作用于 DTO 字段） | 批量状态更新类接口 |
| 异常无兜底 | `GlobalExceptionHandler` 未处理 `Exception`，错误响应结构不统一 | 全部模块 |
| 密码入日志 | `WebLogAspect` 记录请求参数，登录/注册接口的密码明文落盘 | 管理员登录、会员登录/注册 |
| 状态机无守卫 | 状态流转接口不校验当前状态是否允许目标转换 | 订单发货/关闭、退货处理 |
| 越权风险 | 前台接口按传入的 `memberId` 操作资源，未强制取当前登录会员 | 收货地址、收藏、关注等 |

| 1 | **P0** | **`/order/paySuccess` 可被任意登录会员利用**：无验签、无金额比对、无订单归属校验、无幂等。可标记他人订单为已支付；`/alipay/query` 带补单副作用且**匿名可达** | `OmsPortalOrderController` | 购物车与下单-前台 |
